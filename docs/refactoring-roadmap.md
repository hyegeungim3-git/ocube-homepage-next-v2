> 상태: **미적용 작업 계획**. 체크되지 않은 항목을 현재 구현으로 간주하지 않는다.

> 키가 되어 "문구 수정은 데이터에서" 가 오히려 어려워진다. 그래서 **한국어 원문을 키로 쓰는

> 화면 코드는 한국어를 그대로 품고 있어 읽기 쉽고, 번역을 채우는 자리도 예전과 같다.
>
> **막혔던 지점은 `<wbr />`.** 한국어는 `"…(OPC-UA·" <wbr /> "Modbus)…"` 처럼 문장이
> 갈라져 있고 영어는 이어 붙인 한 문장으로 번역돼 있다. 그래서 `<T>` 는 자식을 한 줄로 펴서
> (wbr 은 빼고) 찾고, 데이터 쪽 `localized()` 는 `"wbr"` 토큰으로 갈라진 문자열을 먼저 잇는다.
> 예전 생성기가 하던 일을 그대로 옮긴 것이다.

### 이 검수에서 잡은 회귀 4건 (전부 수정)

1. **스티키 헤더의 유리 효과가 죽어 있었다.** 표준 속성 다음 줄에 `-webkit-` 을 손으로 쓰면
   압축기가 둘을 같은 속성으로 보고 뒤엣것만 남긴다 → Chrome 에서 선언이 통째로 죽는다.
   **접두사는 손으로 쓰지 말고 도구에 맡길 것.**
2. **`height:100vh` 폴백 5곳이 사라졌다.** 나란히 쓴 중복 선언은 압축기가 앞엣것을 지운다.
   구형 브라우저 폴백은 `@supports` 로 분리해야 살아남는다.
3. **영어 빈 상태 문구가 한국어로 나왔다.** 사전 열쇠에 `&apos;` 가 들어 있어 JSX 가 그린
   실제 따옴표와 안 맞았다. 사전은 못 찾으면 원문을 그대로 돌려주므로 **오류 없이 조용히 실패**한다.
4. **영문 푸터 주소가 셋 중 둘만 번역됐다.** 같은 원인(열쇠 불일치).

### 검사 방법에서 배운 것

- **목록을 자르고 앞부분만 보고 일반화하지 말 것.** CSS 규칙 대조에서 "값이 다른 것 118개"
  중 앞 25개만 보고 "전부 동등 변환" 이라 판단했는데, 1번 회귀가 잘라낸 뒤쪽에 있었다.
- **숨은 요소를 훑는 검사가 따로 필요하다.** 3번은 평소 숨어 있는 안내문이라
  '보이는 글자' 검사에 걸리지 않았다. 필터에서 결과가 0건일 때만 드러난다.
- **-/+ 방향을 확인할 것.** 3번을 처음에 'v2 가 영문화한 개선' 으로 잘못 읽었다.
  배포된 두 사이트를 직접 받아 비교하고 나서야 방향이 반대임을 알았다.
