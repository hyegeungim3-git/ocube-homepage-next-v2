# 먼저 밟은 지뢰

이 저장소를 만들면서 **실제로 겪은** 것만 적는다. 일반론이 아니라, 여기서 한 번 이상
사람을 넘어뜨린 것들이다. 새로 오면 여기부터 읽는 편이 빠르다.

각 항목은 `증상 → 원인 → 대처` 순이고, 마지막 줄은 **어떻게 하면 다시 안 밟는가** 다.

---

## 1. 환경·빌드

### `npm ci` 가 클론 직후에만 실패한다

- **증상** 내 컴퓨터에서는 `build`·`test` 가 다 통과하는데, CI(또는 새로 클론한 사람)에서만
  `npm ci` 가 `Missing: @emnapi/runtime@… from lock file` 로 죽는다.
- **원인** `node_modules` 가 이미 있는 자리에서 잠금 파일을 만들면, npm 이 설치된 트리를
  기준 삼아 **이 플랫폼에 필요 없는 선택적 의존성(다른 OS 용 wasm 대체 구현)을 빼고** 쓴다.
  Windows 에서 만든 잠금 파일로 Linux 러너가 설치할 수 없게 된다.
- **대처** `package.json` 만 둔 빈 디렉터리에서 `npm install --package-lock-only` 로 만들어 가져온다.
  같은 자리에서 `--package-lock-only` 를 돌리면 아무것도 안 바뀌거나 오히려 더 줄어든다.
- **재발 방지** 의존성을 건드렸으면 **빈 디렉터리에서 `npm ci` 가 되는지** 확인하고 커밋한다.

### `npm run verify` 가 `ModuleNotFoundError: No module named 'bs4'` 로 죽는다

- 게이트는 **파이썬 스크립트**다. Node 만 깔아서는 돌지 않는다.
- `pip install -r scripts/requirements.txt`.
- 이 요구사항이 어디에도 적혀 있지 않아 CI 를 처음 켰을 때 바로 걸렸다. 지금은 README
  '실행' 절과 CI 워크플로 양쪽에 적혀 있다.

### 개행문자가 검증에서 세 번 헛신호를 냈다

- `.gitattributes` 를 나중에 넣으면 **이미 체크아웃돼 있던 파일은 CRLF 로 남는다.**
  저장소(커밋본)와 CI·배포는 LF 인데 내 작업트리만 CRLF 라, 빌드 산출물을 바이트로 비교하면
  "달라졌다" 고 나온다. 서로 다른 검증에서 세 번 같은 헛신호가 나왔다.
- 한 번에 정리: `git add --renormalize .` 로 커밋본을 확인하고, 추적 파일을 지운 뒤
  `git checkout -- .` 로 다시 받는다(`eol=lf` 가 걸려 LF 로 내려온다).
- **판정 요령**: 바이트가 다르면 먼저 `
` 을 `
` 으로 바꿔 비교해 본다.
  거기서 같아지면 내용 차이가 아니라 개행 차이다.

### 클론하자마자 `format:check` 가 빨간불

- **원인** Windows 가 CRLF 로 체크아웃한다. Prettier 는 LF 를 기대한다.
- **대처** `.gitattributes` 에 `* text=auto eol=lf`. 이미 들어 있다.
- **재발 방지** 새 파일 종류를 추가하면 `.gitattributes` 의 바이너리 예외를 확인한다.

### `npm run build` 가 `EBUSY: rmdir out` 으로 죽는다

- 로컬 확인 서버가 `out/` 을 잡고 있는 것이다. 서버를 끄고 다시 빌드한다.

### 게이트가 `<body>` 직속 요소를 안 보던 때가 있었다

- 토스트를 상시 렌더로 바꿔 **정적 HTML 이 46쪽에서 달라졌는데 게이트는 초록**이었다.
  header·m-panel·main·footer 만 비교하고 있었기 때문이다 — 토스트·맨 위로 버튼·
  스크롤 진행 바가 전부 그 밖에 있다.
- `body-extra` 검사를 추가해 막았다(48쪽 × 12항목 = 576건).
- **교훈은 검사 항목이 아니라 태도다**: 게이트가 초록이어도 "그 자리를 보고 있었나" 를 묻는다.

### `verify` 가 낡은 `out/` 을 보고 전부 통과를 준다

- 빌드가 실패했는데 이전 `out/` 이 남아 있으면 게이트가 통과해 버린다.
- `verify-fidelity.py` 에 **낡음 감지**를 넣어 두었다(소스가 `out/` 보다 새로우면 멈춘다).
  그래도 습관은 `build && verify` 를 붙여 쓰는 것.

## 2. 스타일 (SCSS → 번들)

### 손으로 쓴 벤더 접두사가 표준 속성을 죽인다 ⚠️ 실제로 화면이 깨졌다

- **증상** 스크롤하면 헤더 뒤 본문 글자가 그대로 비쳐 읽힌다(유리 효과가 사라짐).
- **원인** 소스에 이렇게 써 두면

  ```scss
  backdrop-filter: saturate(1.2) blur(14px);
  -webkit-backdrop-filter: saturate(1.2) blur(14px); /* ← 손으로 쓴 접두사 */
  ```

  압축기가 **둘을 같은 속성으로 보고 뒤엣것만** 남긴다. Chrome 은 `-webkit-` 별칭을
  지원하지 않으므로 선언이 통째로 죽는다.

- **대처** 접두사를 쓰지 않는다. 도구가 붙여 준다(실제로 접두사를 안 쓴 규칙들은 멀쩡했다).
- **재발 방지** `src/styles` 에서 `-webkit-` 을 직접 쓰기 전에 정말 필요한지 의심할 것.

### 구형 브라우저 폴백이 조용히 사라진다

- **증상** `height: 100vh; height: 100dvh;` 처럼 나란히 쓴 폴백에서 **앞엣것이 지워진다**.
  `dvh` 를 모르는 브라우저에서 높이가 통째로 무너진다.
- **대처** `@supports` 로 분리한다. 압축기가 블록을 넘나들며 합치지 못한다.

  ```scss
  .hero {
    min-height: 100vh;
    @supports (height: 100dvh) {
      min-height: 100dvh;
    }
  }
  ```

### 좁은 화면에서 헤더 메뉴가 KR/EN 을 침범한다 — **알려진 상태, 고치지 않기로 함**

- **증상** 1150px 이하에서 마지막 메뉴 항목(Company)이 KR/EN 알약과 겹친다.
  실측 겹침: 1100 +12px · 1024 +50px · 901 +112px (호버하지 않은 평상시 기준).
- **원인** 메뉴는 `wrap` 정중앙에 절대배치인데, 로고 92 + 메뉴 내용 496 + 오른쪽 묶음 307 +
  여백이 그 폭에 **물리적으로 안 들어간다.** 항목은 `flex:0 0 auto`·`nowrap` 이라 줄지 않는다.
- **먼저 만든 판(`ocube-next`)도 숫자까지 동일하다** — v2 가 만든 회귀가 아니다.
- **2026-08-13 사용자 결정: 지금대로 둔다.** 근본 해결은 데스크톱 메뉴 기준폭을 900 → 1150 으로
  올리거나(1024·1100 사용자가 햄버거를 보게 된다) 좁은 구간에서 문의하기 버튼을 감추는
  (155px 확보) 선택이라, 둘 다 설계 변경이기 때문이다.
- **그러니 이걸 '버그' 로 보고 임의로 고치지 말 것.** 다시 다루려면 위 두 선택지 중 하나를
  사용자와 정하고 시작한다.
- 다만 **메가 메뉴가 더 벌어지던 몫은 줄여 두었다**(1100: 97→27 · 1024: 97→65 · 1280↑: +27→−24).
  그 상한(`min(618px, max(540px, calc(100% - 662px)))`)의 근거는 `_mega-menu.scss` 주석에 있다.

### `@use` 차례가 곧 캐스케이드다

- `src/styles/site.scss` 의 불러오는 순서를 바꾸면 화면이 **조용히** 달라진다.
  파일을 추가할 때는 원래 `order.json` 이 정하던 자리에 넣는다.

### 헤딩 레벨만 바꿨는데 카드 크기가 변한다

- `h4` → `h3` 처럼 태그만 올려도 조상 스코프의 태그 셀렉터(`.sol-intro h2` 같은 것)가
  얹혀 여백이 달라진다. **전/후 요소 스크린샷 픽셀 비교**로 확인하는 게 확실하다.

## 3. 다국어

### 사전이 조용히 빗나간다 ⚠️ 영어 화면에 한국어가 남았다

- **증상** 영어 화면 일부가 한국어로 나온다. 오류는 없다.
- **원인** 사전 열쇠가 **화면에 그려지는 글자와 정확히 같아야** 한다. 어긋나는 흔한 이유 둘:
  - 열쇠에 `&apos;` 같은 **HTML 엔티티**가 들어 있다. JSX 는 그릴 때 진짜 따옴표로 바꿔
    넘기므로 맞지 않는다.
  - 화면 문자열과 사전 열쇠의 **띄어쓰기·괄호 표기가 미세하게 다르다**
    (`…1로31길 18` vs `…1로31길 18 (본사)` vs `…1로 31길 18`).
- **대처** 사전은 못 찾으면 **원문을 그대로 돌려준다** — 그래서 오류가 안 난다.
  `tests/unit/dictionary.test.ts` 가 엔티티는 막아 준다. 띄어쓰기 차이는 못 막으니,
  영어 화면을 실제로 열어 확인하는 습관이 필요하다.
- **재발 방지** 번역을 추가하면 **빌드한 `out/en/*.html` 에서 한국어를 훑는다**
  (숨은 요소·`alt`·`aria-label` 까지). 보이는 글자만 보면 놓친다 — 아래 6번 참조.

### 보이지 않는 글자를 원문에 넣으면 사전이 빗나간다

- 좁은 화면에서 `·` 이 줄머리로 내려가는 것을 막으려고 한국어 원문에
  **낱말 이음쇠(U+2060 WORD JOINER)** 를 넣는다. 눈에 보이지 않지만 **문자열은 달라진다.**
- 사전 열쇠는 이 글자를 모르므로 그대로 두면 번역을 못 찾는다 →
  `normalizeKey` 가 걷어낸다. `tests/unit/dictionary.test.ts` 가 이 규칙을 지킨다
  (규칙을 지우면 그 검사가 빨간불이 되는 것까지 확인했다).
- 소스에는 **보이지 않는 글자를 그대로 넣지 말 것.** 스크립트로 넣고, 정규식 안에서는
  `\u2060` 이스케이프로 적는다 — 그래야 다음 사람이 왜 문자열이 안 맞는지 헤매지 않는다.

### 영어 화면의 자산 경로

- 영어 화면은 `/en/` 아래라 자산이 한 단계 위에 있다. 반드시 `assetPath(경로, lang)` 을 태운다.
  데이터로 이미지 경로를 뺄 때 이걸 빠뜨려 두 번 깨졌다.

### `<wbr />` 와 `{" "}`

- 줄바꿈 힌트 `<wbr />` 가 문자열 중간에 있으면 **정규식으로 문장을 찾는 스크립트가 빗나간다**.
  치환할 때는 태그를 벗긴 평문끼리 비교하는 편이 안전하다.
- JSX 의 `{" "}` 는 눈에 안 보이지만 **인라인 요소 사이의 실제 간격**이다. 반복문으로 바꿀 때
  빠뜨리면 글자가 붙는다(실제로 진행 바 번호가 `01AX02EMBEDDED` 로 붙었다).

### 로고를 새로 넣을 때의 규격

- 고객사 로고는 **280x90 투명 캔버스**에 내용을 가운데로 넣는다. 가로형은 폭 200,
  세로로 뭉친 것(비율 2.2 미만)은 높이 82 에 맞춘다 — 기존 로고들과 광학 크기가 맞는다.
- 로고월 CSS 는 `max-height:34px` 로 **높이**를 묶는다. 그래서 심벌이 글자 위에 얹힌
  세로형 로고는 글자가 뭉갠다. 그런 로고는 **심벌과 글자를 가로로 나란히** 재배치해야 읽힌다
  (하이박이 그랬다 — 실렌더로 봐야만 드러난다).
- 흰 배경 JPG 는 알파를 뽑아 투명하게 만든다. 뒤 배경이 `#fafbfd` 라 흰 상자가 비친다.

## 4. React · Next

### 효과 안에서 상태를 바꾸지 않는다

- 브라우저 상태(스크롤·미디어 쿼리·마운트 여부)는 `useEffect`+`useState` 가 아니라
  `useSyncExternalStore` 로 읽는다. 린트(`react-hooks/set-state-in-effect`)가 막는다.
  이 규칙에 세 번 걸렸고, 세 번 다 외부 저장소나 파생값으로 바꾸는 게 정답이었다.

### 서버에서 그리면 정적 HTML 이 달라진다

- 예전에 스크립트가 하이드레이션 뒤에 붙이던 속성을 서버에서 그리면 **게이트가 잡는다.**
  잡히는 게 정상이다 — 목록을 읽고 "내가 의도한 그것" 인지 확인한 뒤 기준선을 갱신한다.

### 형제 컴포넌트가 상태를 나눠 가질 때

- 위로 올리면 `PageShell` 이 클라이언트 컴포넌트가 되어 **화면 본문까지 브라우저 번들**로
  들어간다. 작은 바깥 저장소(`behavior/mobile-menu.ts`, `header-scroll.ts`)를 쓴다.

### 효과의 의존성 배열이 곧 '언제 다시 도는가' 다

- 복사 알림의 1.8초 숨김 타이머가 `[shown, message]` 에 매여 있었다. 같은 값을 다시 복사하면
  두 값이 그대로라 **효과가 다시 돌지 않아 첫 클릭 기준 타이머가 그냥 흘렀다** —
  두 번째 알림이 24ms 만에 사라졌다.
- 사용자의 '행위' 마다 다시 돌아야 하면, 값이 아니라 **누를 때마다 늘어나는 번호(seq)** 를
  상태에 넣어 의존성으로 삼는다.

### 보조기술이 읽는 알림은 미리 만들어 둔다

- 스크린리더는 이미 있던 live region 의 **내용이 바뀌는 것**을 읽는다. 글자를 담은 채로
  노드를 새로 꽂으면 읽지 않고 지나칠 수 있다. 빈 상자를 처음부터 그려 두고 글자만 채운다.

### 클라이언트 컴포넌트에서 사전을 부르지 않는다

- `t()` 를 클라이언트에서 부르면 사전 24개 파일이 통째로 번들에 실린다.
  문구는 서버에서 번역해 props 로 넘긴다(`HomeHero` 가 그 예).

## 5. 생성물을 직접 고치지 않기

- `public/assets/site2.css` 와 `site2.js` 는 **없어졌다.** 예전에는 조각을 이어 붙여 만드는
  생성물이었고, 그걸 직접 고치면 다음 빌드에서 조용히 사라졌다(두 번 겪었다).
- 지금 남아 있는 생성물 성격의 것: `baseline/`(기준선), `tests/visual/__screenshots__/`.
  둘 다 **확인 먼저, 갱신 나중.**

## 6. 검사 방법 자체의 함정

여기가 가장 값어치 있다. **검사에 안 걸린 것과 없는 것은 다르다.**

| 함정                              | 무슨 일이 있었나                                                                      | 어떻게                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 목록을 잘라 앞부분만 보기         | CSS 차이 118개 중 앞 25개만 보고 "전부 동등 변환" 이라 판단 → 유리 효과 회귀를 놓쳤다 | 요약할 거면 **전량을 분류**하고, 분류 안 되는 것만 남겨 본다 |
| 숨은 요소 빼고 보기               | 필터 결과가 0건일 때만 뜨는 안내문이 한국어로 남아 있었다                             | 텍스트 노드를 훑을 때 `hidden` 요소와 속성값까지 포함        |

### 스크린샷 기본 허용오차가 옅은 변화를 삼킨다

- 유리 효과가 통째로 죽었는데 스크린샷 검사가 **통과**했다. `toHaveScreenshot` 기본
  `threshold: 0.2` 는 픽셀당 색 거리 기준이라, 93% 불투명 헤더 뒤로 옅게 비치는 흐림 정도는
  '같다' 고 본다.
- 옅은 효과를 지키려면 그 장면만 `threshold: 0, maxDiffPixels: 0` 으로 조인다.
  조인 뒤 실측: 효과를 죽이면 12,910픽셀 차이로 실패, 정상은 2회 연속 통과(흔들림 없음).
- **검사를 넣었으면 일부러 되돌려 실패하는지 확인할 것.** 이 두 검사 모두 그 확인에서
  처음엔 '안 잡힘' 이 나왔다.

### 허용오차를 **비율**로 주면 큰 화면일수록 눈이 먼다

`maxDiffPixelRatio` 는 이미지 면적에 비례한다. 0.002 로 두었더니 —

| 화면        | 크기      | 허용된 차이 | 결과                                       |
| ----------- | --------- | ----------- | ------------------------------------------ |
| 홈 데스크톱 | 1440×6182 | 17,804 px   | **푸터 주소 세 줄이 통째로 바뀌어도 통과** |
| 홈 모바일   | 375×5992  | 4,494 px    | 같은 변경이 걸림                           |

즉 **큰 화면일수록 관대해진다** — 정작 정보량이 많은 쪽이 덜 지켜졌다.
기준 이미지를 같은 기계에서 만드는 한 안티에일리어싱 차이는 사실상 0 이므로
비율은 낮게(`0.0001`) 잡고, 픽셀별 차이는 `threshold` 에 맡긴다.

일부러 옛 주소를 되돌려 시험했더니 조이기 전에는 데스크톱이 통과하고 모바일만 실패,
조인 뒤에는 **네 장 전부 실패**했다.

### 스크린샷이 '안정되지 않는' 진짜 이유는 대개 JS 애니메이션

허용오차를 조이자 홈에서 "두 장이 안정되지 않는다" 로 실패했다. 두 장을 겹쳐 보니
차이가 히어로 카피(`y 253~479`)에만 있었다 — **타자기 효과가 타이핑 중**이었다.

- CSS `animation:none` 은 `setTimeout` 으로 글자를 하나씩 붙이는 코드를 못 멈춘다.
- `playwright.config` 의 `reducedMotion: "reduce"` 는 `testInfo.project.use` 에는 분명히
  들어 있는데 페이지에서 `matchMedia(...).matches` 가 **false** 였다. 설정 배관을 믿지 말고
  촬영 직전에 `page.emulateMedia({ reducedMotion: "reduce" })` 로 못을 박고,
  남은 타이머까지 끄고 글자를 전부 드러낸 상태로 고정한다(`freezeForShot`).
- 원인을 찾을 때는 **`-previous.png` 와 `-actual.png` 를 겹쳐 차이 bbox 를 찍어 보는 것**이
  가장 빠르다. 어느 영역이 움직이는지 한 번에 나온다.

### `networkidle` 로 기다리지 않는다

`freezeForShot` 이 `waitForLoadState("networkidle")` 로 기다리다 배경 요청이 끊기지 않아
60초 시한을 넘겨 산발적으로 실패했다(en/index 모바일). **무엇을 기다리는지 분명한 조건**으로
바꾼다 — 여기서는 "아직 `complete` 가 아닌 이미지들의 load/error" 를 기다린다.
바꾼 뒤 3회 연속 34/34 통과, 실행 시간도 20초 → 15초로 줄었다.

### 픽셀로 판정하면 안 되는 화면

- `location` 두 쪽은 구글 지도 iframe 때문에 **같은 빌드끼리도 10% 가까이** 다르게 찍힌다.
  이 화면을 픽셀로 볼 때는 지도를 가리거나 제외한다.

### 셸·스크립트

- 같은 문자열이 여러 영역에 있으면 **전역 치환 금지**. 구간을 먼저 잘라내고 바꾼다
  (푸터 문구를 지우려다 히어로 경로 표시까지 지운 적 있다).
- 중첩된 같은 태그를 인덱스로 잘라내면 안쪽 닫는 태그에서 끊긴다. **잘라낸 뒤 태그 균형을 센다.**
- 정규식 이스케이프(`\b` 등)를 heredoc → python 으로 흘려보내면 깨진다. 스크립트 파일로 쓴다.
- 삭제 예정 구간이 있는 문서에서 `count=1` 치환은 **엉뚱한 곳에 맞는다.** 삭제 후에 치환한다.

## 7. 배포

- Pages 는 **하위 경로**(`/저장소명/`)에 올라간다. Next 런타임 청크가 절대경로라
  `PAGES_BASE_PATH` → `assetPrefix` 주입이 필요하다. 워크플로가 이미 한다.
- 배포 직후 라이브를 확인할 때는 **캐시**를 의심한다. 쿼리스트링을 붙여 받는다.
- Actions 가 초록이어도 Pages 재빌드가 끝나기 전에는 옛 내용이 보인다. 실제 문자열로 확인한다.

## 8. 알아두면 좋은 잠재 지점 (지금은 문제 없음)

- **압축기가 셀렉터를 `:is()` 로 합치면 특이도가 올라간다.** `.media-duo` 는 원본에서
  (0,1,0)이었는데 `:is(.media-duo, .media-duo:has(…))` 로 합쳐지며 (0,2,0)이 됐다.
  지금은 덮어쓰는 규칙이 없어 결과가 같다(8쪽 × 3폭 실측 일치). 나중에 그 사이 특이도로
  덮으려 하면 원본과 갈린다.
- **`-webkit-` 접두사는 도구 기본값에 기대고 있다.** `browserslist` 를 고정하지 않았으므로
  도구의 기본 대상이 올라가면 접두사가 조용히 사라질 수 있다.
  지금은 `tests/unit/built-css.test.ts` 가 개수를 지켜본다.
- **압축기가 함수 나열 사이 공백을 지운다**(`saturate(1.2)blur(14px)`). Chrome 계산값은
  같고 사이트 전역에서 이미 그래 왔다. 구형 WebKit 파서는 이 환경에서 확인하지 못했다.
- **`.h-badge span` 처럼 어느 화면에도 없는 셀렉터**가 스타일시트에 남아 있다.
  고칠 때 '실제로 쓰이는 자리인지' 부터 확인하면 헛일을 줄인다.
