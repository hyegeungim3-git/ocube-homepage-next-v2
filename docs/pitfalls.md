# 먼저 밟은 지뢰

이 저장소를 만들면서 **실제로 겪은** 것만 적는다. 일반론이 아니라, 여기서 한 번 이상
사람을 넘어뜨린 것들이다. 새로 오면 여기부터 읽는 편이 빠르다.

각 항목은 `증상 → 원인 → 대처` 순이고, 마지막 줄은 **어떻게 하면 다시 안 밟는가** 다.

---

## 1. 환경·빌드

### `npm ci` 가 클론 직후에만 실패한다

- **증상** 내 컴퓨터에서는 `build`·`test` 가 다 통과하는데, CI(또는 새로 클론한 사람)에서만
  `npm ci` 가 `Missing: @emnapi/runtime@… from lock file` 로 죽는다.
- **원인** `node_modules` 가 이미 있는 자리에서 잠금 파일을 만들면, npm 이 설치된 트리를
  기준 삼아 **이 플랫폼에 필요 없는 선택적 의존성(다른 OS 용 wasm 대체 구현)을 빼고** 쓴다.
  Windows 에서 만든 잠금 파일로 Linux 러너가 설치할 수 없게 된다.
- **대처** `package.json` 만 둔 빈 디렉터리에서 `npm install --package-lock-only` 로 만들어 가져온다.
  같은 자리에서 `--package-lock-only` 를 돌리면 아무것도 안 바뀌거나 오히려 더 줄어든다.
- **재발 방지** 의존성을 건드렸으면 **빈 디렉터리에서 `npm ci` 가 되는지** 확인하고 커밋한다.

### `npm run verify` 가 `ModuleNotFoundError: No module named 'bs4'` 로 죽는다

- 게이트는 **파이썬 스크립트**다. Node 만 깔아서는 돌지 않는다.
- `pip install -r scripts/requirements.txt`.
- 이 요구사항이 어디에도 적혀 있지 않아 CI 를 처음 켰을 때 바로 걸렸다. 지금은 README
  '실행' 절과 CI 워크플로 양쪽에 적혀 있다.

### 클론하자마자 `format:check` 가 빨간불

- **원인** Windows 가 CRLF 로 체크아웃한다. Prettier 는 LF 를 기대한다.
- **대처** `.gitattributes` 에 `* text=auto eol=lf`. 이미 들어 있다.
- **재발 방지** 새 파일 종류를 추가하면 `.gitattributes` 의 바이너리 예외를 확인한다.

### `npm run build` 가 `EBUSY: rmdir out` 으로 죽는다

- 로컬 확인 서버가 `out/` 을 잡고 있는 것이다. 서버를 끄고 다시 빌드한다.

### `verify` 가 낡은 `out/` 을 보고 528/528 을 준다

- 빌드가 실패했는데 이전 `out/` 이 남아 있으면 게이트가 통과해 버린다.
- `verify-fidelity.py` 에 **낡음 감지**를 넣어 두었다(소스가 `out/` 보다 새로우면 멈춘다).
  그래도 습관은 `build && verify` 를 붙여 쓰는 것.

## 2. 스타일 (SCSS → 번들)

### 손으로 쓴 벤더 접두사가 표준 속성을 죽인다 ⚠️ 실제로 화면이 깨졌다

- **증상** 스크롤하면 헤더 뒤 본문 글자가 그대로 비쳐 읽힌다(유리 효과가 사라짐).
- **원인** 소스에 이렇게 써 두면

  ```scss
  backdrop-filter: saturate(1.2) blur(14px);
  -webkit-backdrop-filter: saturate(1.2) blur(14px); /* ← 손으로 쓴 접두사 */
  ```

  압축기가 **둘을 같은 속성으로 보고 뒤엣것만** 남긴다. Chrome 은 `-webkit-` 별칭을
  지원하지 않으므로 선언이 통째로 죽는다.

- **대처** 접두사를 쓰지 않는다. 도구가 붙여 준다(실제로 접두사를 안 쓴 규칙들은 멀쩡했다).
- **재발 방지** `src/styles` 에서 `-webkit-` 을 직접 쓰기 전에 정말 필요한지 의심할 것.

### 구형 브라우저 폴백이 조용히 사라진다

- **증상** `height: 100vh; height: 100dvh;` 처럼 나란히 쓴 폴백에서 **앞엣것이 지워진다**.
  `dvh` 를 모르는 브라우저에서 높이가 통째로 무너진다.
- **대처** `@supports` 로 분리한다. 압축기가 블록을 넘나들며 합치지 못한다.

  ```scss
  .hero {
    min-height: 100vh;
    @supports (height: 100dvh) {
      min-height: 100dvh;
    }
  }
  ```

### `@use` 차례가 곧 캐스케이드다

- `src/styles/site.scss` 의 불러오는 순서를 바꾸면 화면이 **조용히** 달라진다.
  파일을 추가할 때는 원래 `order.json` 이 정하던 자리에 넣는다.

### 헤딩 레벨만 바꿨는데 카드 크기가 변한다

- `h4` → `h3` 처럼 태그만 올려도 조상 스코프의 태그 셀렉터(`.sol-intro h2` 같은 것)가
  얹혀 여백이 달라진다. **전/후 요소 스크린샷 픽셀 비교**로 확인하는 게 확실하다.

## 3. 다국어

### 사전이 조용히 빗나간다 ⚠️ 영어 화면에 한국어가 남았다

- **증상** 영어 화면 일부가 한국어로 나온다. 오류는 없다.
- **원인** 사전 열쇠가 **화면에 그려지는 글자와 정확히 같아야** 한다. 어긋나는 흔한 이유 둘:
  - 열쇠에 `&apos;` 같은 **HTML 엔티티**가 들어 있다. JSX 는 그릴 때 진짜 따옴표로 바꿔
    넘기므로 맞지 않는다.
  - 화면 문자열과 사전 열쇠의 **띄어쓰기·괄호 표기가 미세하게 다르다**
    (`…1로31길 18` vs `…1로31길 18 (본사)` vs `…1로 31길 18`).
- **대처** 사전은 못 찾으면 **원문을 그대로 돌려준다** — 그래서 오류가 안 난다.
  `tests/unit/dictionary.test.ts` 가 엔티티는 막아 준다. 띄어쓰기 차이는 못 막으니,
  영어 화면을 실제로 열어 확인하는 습관이 필요하다.
- **재발 방지** 번역을 추가하면 **빌드한 `out/en/*.html` 에서 한국어를 훑는다**
  (숨은 요소·`alt`·`aria-label` 까지). 보이는 글자만 보면 놓친다 — 아래 6번 참조.

### 영어 화면의 자산 경로

- 영어 화면은 `/en/` 아래라 자산이 한 단계 위에 있다. 반드시 `assetPath(경로, lang)` 을 태운다.
  데이터로 이미지 경로를 뺄 때 이걸 빠뜨려 두 번 깨졌다.

### `<wbr />` 와 `{" "}`

- 줄바꿈 힌트 `<wbr />` 가 문자열 중간에 있으면 **정규식으로 문장을 찾는 스크립트가 빗나간다**.
  치환할 때는 태그를 벗긴 평문끼리 비교하는 편이 안전하다.
- JSX 의 `{" "}` 는 눈에 안 보이지만 **인라인 요소 사이의 실제 간격**이다. 반복문으로 바꿀 때
  빠뜨리면 글자가 붙는다(실제로 진행 바 번호가 `01AX02EMBEDDED` 로 붙었다).

## 4. React · Next

### 효과 안에서 상태를 바꾸지 않는다

- 브라우저 상태(스크롤·미디어 쿼리·마운트 여부)는 `useEffect`+`useState` 가 아니라
  `useSyncExternalStore` 로 읽는다. 린트(`react-hooks/set-state-in-effect`)가 막는다.
  이 규칙에 세 번 걸렸고, 세 번 다 외부 저장소나 파생값으로 바꾸는 게 정답이었다.

### 서버에서 그리면 정적 HTML 이 달라진다

- 예전에 스크립트가 하이드레이션 뒤에 붙이던 속성을 서버에서 그리면 **게이트가 잡는다.**
  잡히는 게 정상이다 — 목록을 읽고 "내가 의도한 그것" 인지 확인한 뒤 기준선을 갱신한다.

### 형제 컴포넌트가 상태를 나눠 가질 때

- 위로 올리면 `PageShell` 이 클라이언트 컴포넌트가 되어 **화면 본문까지 브라우저 번들**로
  들어간다. 작은 바깥 저장소(`behavior/mobile-menu.ts`, `header-scroll.ts`)를 쓴다.

### 클라이언트 컴포넌트에서 사전을 부르지 않는다

- `t()` 를 클라이언트에서 부르면 사전 24개 파일이 통째로 번들에 실린다.
  문구는 서버에서 번역해 props 로 넘긴다(`HomeHero` 가 그 예).

## 5. 생성물을 직접 고치지 않기

- `public/assets/site2.css` 와 `site2.js` 는 **없어졌다.** 예전에는 조각을 이어 붙여 만드는
  생성물이었고, 그걸 직접 고치면 다음 빌드에서 조용히 사라졌다(두 번 겪었다).
- 지금 남아 있는 생성물 성격의 것: `baseline/`(기준선), `tests/visual/__screenshots__/`.
  둘 다 **확인 먼저, 갱신 나중.**

## 6. 검사 방법 자체의 함정

여기가 가장 값어치 있다. **검사에 안 걸린 것과 없는 것은 다르다.**

| 함정                              | 무슨 일이 있었나                                                                      | 어떻게                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 목록을 잘라 앞부분만 보기         | CSS 차이 118개 중 앞 25개만 보고 "전부 동등 변환" 이라 판단 → 유리 효과 회귀를 놓쳤다 | 요약할 거면 **전량을 분류**하고, 분류 안 되는 것만 남겨 본다 |
| 숨은 요소 빼고 보기               | 필터 결과가 0건일 때만 뜨는 안내문이 한국어로 남아 있었다                             | 텍스트 노드를 훑을 때 `hidden` 요소와 속성값까지 포함        |
| `-`/`+` 방향 안 보기              | 회귀를 "개선" 으로 잘못 읽었다                                                        | 어느 쪽이 원본인지 매번 확인                                 |
| 스크롤 직후 즉시 측정             | `scroll-behavior:smooth` 때문에 아직 안 움직였는데 값을 읽어 6쪽에서 오탐             | 실제 `scrollY` 도달까지 기다린다                             |
| 애니메이션 도중 촬영              | 카운터가 `0` 또는 중간값으로 찍힌다                                                   | 최종값은 2.5초 뒤                                            |
| 지연 이미지 안 깨우기             | `naturalWidth===0` 을 '깨진 이미지' 로 오판                                           | 끝까지 스크롤해 깨운 뒤 측정하거나 URL 로 확인               |
| 대비를 부모 배경으로 계산         | `position:fixed` 헤더 글자가 흰 body 기준으로 계산돼 오탐 4건                         | 조상 알파를 합성하고, 그라디언트는 첫 색 스톱을 파싱         |
| `.sr-only` 를 대비 검사에 포함    | 1×1px 로 숨긴 표 설명이 대비 미달로 잡혔다                                            | 시각적으로 숨긴 것은 제외                                    |
| 합성 이벤트로 `:hover` 기대       | CSS `:hover` 는 실제 포인터가 있어야 발동                                             | 규칙 존재로 확인하거나 실제 이동                             |
| 자동 전환 요소를 다른 시점에 촬영 | 슬라이더가 서로 다른 장을 찍어 차이로 보임                                            | 첫 장에 고정하고 촬영                                        |
| 커밋됐다고 포함된 줄 알기         | `.gitignore` 의 `*.mp4` 가 시연 영상을 막아 라이브만 404                              | 자산 추가 후 `git status` 로 실제로 잡히는지 확인            |

### 셸·스크립트

- 같은 문자열이 여러 영역에 있으면 **전역 치환 금지**. 구간을 먼저 잘라내고 바꾼다
  (푸터 문구를 지우려다 히어로 경로 표시까지 지운 적 있다).
- 중첩된 같은 태그를 인덱스로 잘라내면 안쪽 닫는 태그에서 끊긴다. **잘라낸 뒤 태그 균형을 센다.**
- 정규식 이스케이프(`\b` 등)를 heredoc → python 으로 흘려보내면 깨진다. 스크립트 파일로 쓴다.
- 삭제 예정 구간이 있는 문서에서 `count=1` 치환은 **엉뚱한 곳에 맞는다.** 삭제 후에 치환한다.

## 7. 배포

- Pages 는 **하위 경로**(`/저장소명/`)에 올라간다. Next 런타임 청크가 절대경로라
  `PAGES_BASE_PATH` → `assetPrefix` 주입이 필요하다. 워크플로가 이미 한다.
- 배포 직후 라이브를 확인할 때는 **캐시**를 의심한다. 쿼리스트링을 붙여 받는다.
- Actions 가 초록이어도 Pages 재빌드가 끝나기 전에는 옛 내용이 보인다. 실제 문자열로 확인한다.
